# تحديث أمان نظام المتحدة — النسخة المحلية التجريبية

## الإصلاحات المطلوبة

1. إلغاء زر/قائمة تبديل الأدوار بعد تسجيل الدخول، وإلغاء أزرار الانتحال داخل شاشة الصلاحيات. تبقى صلاحية الحساب مرتبطة بالهوية الموثقة من الخادم، ولا يجوز رفعها باختيار جديد في الواجهة.
2. إزالة قائمة كلمات مرور المستخدمين، والملء التلقائي لكلمة المرور، وكشفها من شاشة الدخول. المالك نفسه لا يستطيع استرجاع كلمة المرور الأصلية؛ يمكنه **إعادة تعيين** كلمة مؤقتة تظهر مرة واحدة في شاشة إدارة المستخدمين.
3. توفير **حذف الأدوار** لصاحب الحساب المالك فقط. لا يمكن حذف دور `super_admin`، وعند حذف دور مرتبط بمستخدمين يجب تعيين دور بديل لا يكون مالك النظام. يجري تحديث المستخدمين وعضوياتهم في SQLite.
4. `/api/state` لم تعد تسمح بالقراءة/الكتابة قبل تسجيل الدخول. لا تُرسل حقل `password_hash` لأي واجهة. التغييرات على جداول الأدوار والمستخدمين محمية من حفظ JSON العام، وإجراءاتها تمر عبر API بإذن المالك.
5. حفظ الجلسات بخاصية Cookie `HttpOnly; SameSite=Strict` على خادم يعمل محليًا 127.0.0.1. تسجيل الخروج يُبطل الجلسة.
6. كلمات المرور الجديدة أو المعاد تعيينها تُحفظ باستخدام PBKDF2-HMAC-SHA256 مع Salt مستقل. حسابات قاعدة البيانات التجريبية القديمة تُرقّى آليًا عند تسجيل الدخول الصحيح.
7. أضيف خيار **تغيير كلمة مروري** لكل مستخدم بعد دخوله، ويتطلب إدخال كلمة مروره الحالية.

## التشغيل على ويندوز

**قبل التحديث:** أغلق البرنامج، وخذ نسخة احتياطية من:

`%APPDATA%\UES SMART ERP\data\ues_smart_erp.db`

افتح المشروع المعدّل داخل VS Code وشغّل الأوامر في Terminal/PowerShell:

```powershell
npm.cmd install
npm.cmd run build:web
npm.cmd start
```

عند نجاح التشغيل، سجّل الدخول بحساب المالك الذي تستخدمه حاليًا، وغيّر كلمة مروره، ثم اذهب إلى **إدارة المستخدمين والصلاحيات**. في صف كل مستخدم زر **إعادة تعيين**؛ وفي جدول الأدوار زر **حذف الدور** للأدوار القابلة للحذف.

### عند الحذف

- الأدوار التي ترتبط بموظفين تتطلب إعادة إسنادهم أولًا من نافذة تأكيد الحذف.
- دور المالك الأساسي لا يُحذف، حفاظًا على وصول إدارة النظام.
- حذف الدور يؤثر على الصلاحيات اللاحقة، وليس فقط إخفاء الاسم في الجدول.

## نتائج الفحص

- نجح فحص تركيب JavaScript باستخدام Node.js (`node --check`).
- نجح فحص بناء HTML وتجميع ملفات Python.
- نجحت اختبارات HTTP على نسخة مؤقتة من SQLite: منع قراءة بيانات دون تسجيل، دخول دور المبيعات، منع حذف الدور من السيلز، منع تعديل صلاحيات عبر الحالة العامة، تقييد رؤية البيانات، صلاحية حذف الدور للمالك، إعادة إسناد المستخدمين، إعادة تعيين كلمة مرور، إنشاء حساب جديد، وإبطال الجلسة بالخروج.
- تعذر اختبار نافذة Electron واختبار بناء EXE على ويندوز من هذه البيئة؛ يجب إجراؤهما على جهاز ويندوز.
- تعذر تنزيل حزمة Tailwind/Electron هنا بسبب قيود الاتصال؛ نفّذ `npm.cmd install` ثم `npm.cmd run build:web` على جهازك لتوليد CSS النهائي.

## حدود هذه النسخة

هذه نسخة **Desktop محلية تجريبية**. ليست نظام هوية مؤسسيًا موثّق الأمان للاستخدام الفعلي بعد. بعض إجراءات الأعمال ما زالت تحفظ الحالة في سجل JSON محلي، وليست معاملات CRUD مُرحَّلة بالكامل لجداول SQLite العلائقية. تم حظر حفظ المدفوعات من هذا السجل العام إلى أن تُنفّذ عملية مالية موثّقة من الخادم. كذلك لا توجد بعد حماية إنتاجية كاملة لإدارة العملاء عبر أجهزة متعددة، ولا MFA فعلي، ولا تكامل رسمي نشط مع واتساب/OpenAI.

**تنبيه:** قاعدة البيانات المرفقة تجريبية وبها حسابات نموذجية من الإصدار السابق. كلمات مرورها الافتراضية قد تكون معروفة من الوثائق القديمة؛ يجب تغييرها أو إعادة تعيينها قبل إضافة بيانات حقيقية. لا تشارك ملف SQLite أو النسخة القديمة أو أي مفتاح API مع الموظفين.

**تنبيه إضافي:** الحسابات التي أُنشئت في الواجهة القديمة فقط ولم تُسجل في جدول `users` الفعلي قد تحتاج إعادة إنشائها من خلال حساب المالك. بيانات البرنامج في `%APPDATA%` لا تُستبدل عند إعادة تثبيت البرنامج ما لم تحذفها بنفسك؛ لا تحذفها قبل حفظ نسخة احتياطية.
